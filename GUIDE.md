# Guide

This guide is the short operational entry point for running and validating
`jedit`. For architecture doctrine, read [ARCHITECTURE.md](ARCHITECTURE.md).
For the render path and runtime details, read
[ADVANCED_GUIDE.md](ADVANCED_GUIDE.md).

## Run The App

Install dependencies once:

```sh
npm install
```

Start the TUI:

```sh
JEDIT_ECHO_WASM_MODULE=/path/to/echo-wasm-package npm run dev
```

The module must expose the real Echo WASM kernel boundary. Startup fails when
the module cannot be loaded. Once Echo initializes, text operations remain
typed obstructions until Echo can install and invoke Jim's generated Edict
operation package. Jim does not fall back to a local text runtime.

Build the app:

```sh
npm run build
```

`npm run build` compiles TypeScript and copies runtime assets. It does not
generate or execute a legacy contract package.

## Validate The Workspace

Use the normal local gate:

```sh
npm run check
```

That runs:

```text
npm run test:all   (which builds first, then runs spec/ and tests/)
npm run quality
```

Tests may explicitly inject test-only Echo doubles. Product source contains no
fake, fixture, in-memory, or snapshot text authority.

## Generated Operation Corridor

The former Wesley generators and generated TypeScript contract projections were
deleted. They could describe operations, but they could not make those
operations Echo-owned or causally authoritative.

The next executable text path must be generated by Edict and installed into
Echo:

```text
Jim command
-> generated Edict client
-> Echo-installed verified operation
-> Echo admission and scheduler-owned tick
-> opaque Echo receipt
-> basis-pinned bounded observation
```

Until that corridor exists, the product is intentionally non-editing rather
than locally authoritative.

## Echo Witnesses

The product startup path loads Echo directly. Unit tests use explicit
test-only doubles where isolation is required.

The real Echo WASM witness is opt-in:

```sh
ECHO_WARP_WASM_DIR=/path/to/echo/crates/warp-wasm \
  scripts/run-real-echo-wasm-stack-witness.sh
```

That script asks Echo to build its own WASM package boundary and then runs the
jedit witness with `JEDIT_ECHO_WASM_MODULE` pointed at the resulting module.

Current status: the witness rebuilds Echo's WASM package and proves that Jim can
load and initialize that kernel. It deliberately does not install a Jim package,
submit a text intent, drive the scheduler, or claim a text receipt. Those
capabilities belong to the forthcoming Echo/Edict corridor.

For agent use, prefer the shell witness above. A future MCP surface can wrap the
same command after retained evidence and replay output are strong enough to be
worth exposing through a protocol.

Agents that need machine-readable kernel smoke output should call the Node CLI
directly:

```sh
JEDIT_ECHO_WASM_MODULE=/path/to/echo-wasm.js \
  node scripts/jedit-echo-kernel-smoke.mjs --json
```

The JSON output proves only that Jim loaded and initialized the configured Echo
kernel. It does not claim that a Jim text operation ran. Product-shaped text
evidence remains unavailable until Echo installs and invokes the generated Jim
Edict package.

## Current Runtime Truth

In production, Echo/session authority owns causal text. `EditorState.lines` is
a disposable visible projection populated from Echo observations. Proposed
edits do not mutate it; an admitted operation must return a new basis-pinned
reading before changed text becomes visible. It is never saved or recovered as
authority.

Source rendering, Markdown preview, drawers, syntax highlighting, and footer
state are projections over that visible/session projection.

There is no transitional in-memory executor and no generated-metadata-only
consumer. The first operation to return must be a real installed Edict
`ReplaceRange` operation executed by Echo.
