# Supported Outcome Settlement And `:why`

Status: design note for WF-0108A.

Supported Outcome Settlement is the cross-repo doctrine that replaces the
temporary ULTRAGOLD working name. For jedit, the doctrine matters because
`:why` is the user-facing place where Jim projects runtime evidence into editor
language without overstating what happened.

## Jim Boundary

Jim owns:

- editor command vocabulary;
- Vim/Jim product wording;
- `:why` human text and JSON witness shape;
- repair affordances such as rebase, refresh basis, preserve draft, and retry.

Jim does not own:

- Echo admission or scheduler law;
- Continuum support admissibility;
- XYPH Quest settlement;
- proof-tier policy for a foreign authority.

## `:why` Outcome Vocabulary

`:why` should distinguish:

```text
completed
obstructed_repairable
blocked_authority
underdetermined
disputed
failed_invalid
```

For stale basis, the honest product statement is not "the edit failed and
nothing happened." It is:

```text
The edit did not apply because its basis was stale.
Jim preserved or reported a witnessed obstruction.
Repair may require refreshing basis, rebasing the edit, or resolving a conflict.
```

## Mapping To The Golden Loop

Supported Outcome Settlement fits Jim's signature loop:

| Loop step | SOS meaning |
| --- | --- |
| explain | Report the supported outcome and evidence posture. |
| preview | Show the strand neighborhood: actual, counterfactual, obstructed, repair candidates. |
| admit | Submit a new lawful proposal, including repair candidates. |
| recover | Use retained evidence/obstruction posture without fabricating success. |

## Product Rule

Jim may translate generic Echo/Continuum evidence into editor words, but it must
not launder a weak support tier into a stronger claim.

If support is local-only, missing, redacted, obstructed, underdetermined, or
future-proof-slot-only, `:why` must say so.
