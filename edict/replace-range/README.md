# ReplaceRange Edict application

This directory is the Jedit-owned application root for issue #296. It keeps
the authored, built, and evidentiary artifact classes separate:

- `edict.lawpack.json` is the reviewable `jedit.text@1` authoring input;
- `vendor/jedit-text/` is Edict's canonical published lawpack closure;
- `src/ReplaceRange.edict` is the application-owned source;
- `edict.toolchain-lock.json` pins the exact build implementations and
  provider;
- `edict.build-lock.json` pins the exact source closure and emitted artifact
  chain;
- `edict.executable-subject-lock.json` pins the verified executable meaning;
- `.build/` contains disposable provider and compiler outputs;
- `contracts/jedit/lawpacks/replace-range-v1/` remains the independent schema
  and oracle corpus and is not executable input.

## Current executable boundary

The authored source computes flat-text replacement as prefix + replacement +
suffix. Its ordered guard checks the range before slicing, validates the full
original text and replacement as UTF-8, validates both offset prefixes as
UTF-8, and rejects byte-identical replacements. The guard reports a generic
input-constraint refusal; it does not yet produce the domain's typed outcomes.

The imported constant helper has its own small cost declaration. The operation
budget separately includes bounded UTF-8 scan work. Reusing the operation's
entire budget as the constant helper's cost would consume that budget before
accounting for the scans.

The standalone test host supplies bytes to the freshly compiled package. It
checks nine literal replacements, thirteen range, UTF-8 and no-op refusals,
and five host-resource refusals. It performs no native replacement and links
no native rope planner. The package-chain harness runs both the boundary and
flat-text targets, and the build closure includes both test sources.

The toolchain pins Amblicit main `7dbcbc23d72705c5e224fc994a6c767881958912`
and Echo main `d527f47176d506deae30d3ee4bbf36b924e7bb30`. The generated
build and executable-subject locks bind the changed source, vendor publication,
provider and test closure. The relock reproduces the locked package and
verifier-report bytes on macOS; the required CI job checks the package chain on
native Linux. Cross-platform reproduction has not been established for these pins. The
package identity is
`sha256:4baaaf40b2ac67c329c4300562b428eaa08a8f0e7b1ab4034a43a864361ba3fe`.
The package-chain gate checks the exact clean Git toolchains, rebuilds
through the public CLI, verifies the locks, runs both runtime targets and
refuses mutation of authoritative inputs.

This is pure computation. No graph or rope is mutated, no Tick is settled,
and no WAL or recovery evidence is produced. The test host enables Echo's
trusted-host API only in this standalone unpublished test crate. It is not a
production dependency or an alternate editor route. The authored rope algorithm
and generic stateful execution remain unfinished under #296.

## Persistent rope source (in progress, #296)

`rope/src/` holds the schema-2 persistent-rope modules that will replace the
flat-text source above. They are not yet part of the locked package chain.

- `Octets.edict` is generated by `tests/octets-source.mjs`. Amblicit has no
  integer-to-byte conversion and no U8 widening, so the codec reads and writes
  octets through two total 256-leaf comparison trees. Static cost charges a
  list literal at its full size on every call, so the trees use no tables.
- `Codec.edict` encodes the canonical-CBOR atoms of the Head, Branch, Leaf and
  Buffer facts. It also decodes them exactly: a well-typed atom in another
  spelling, with another field set or with trailing bytes is `Malformed`.
- `Identity.edict` declares the schema-2 type ids and computes
  ContentAddressV1 ids through Echo's `echo.dpo@2` identity intrinsics. A
  spec checks every type id against the #404 fixture profile.
- `Rope.edict` holds the arena form of `rope-build.mts`: branch, the two
  rotations, and joinRight, joinLeft and join as bounded folds. The folds use
  a 32-entry path stack and 66 steps, sized for `text.maxTreeHeight = 32`.
  It also holds `find` (the leaf holding an offset), `cut` (prefix and suffix
  by path copy, joining the siblings they pass), fresh leaves, and
  `freshNodes`. `freshNodes` is a breadth-first walk that lists only the
  fresh nodes reachable from the new root, so nodes a rotation discarded are
  never emitted.
- `Build.edict` holds the byte-level parts: `fromBytes` (up to 16,384
  replacement bytes in at most four levels), `locate` and the leaf rewrite
  with its path copy, and the equal-length no-op comparison. Leaf bytes stay
  outside the arena: a stored leaf's are its closure row, and a fresh leaf
  names the replacement or the rewritten leaf.
- `Closure.edict` holds the closure-read selector and the arena it yields.
  The selector expands the boundary paths, both outer spines of each
  sibling off those paths (a join's descent depth is unknown at read time),
  and the no-op range. It never selects leaves, so occurrence k's children
  are edge rows 2k and 2k + 1. Loading decodes and types every row,
  identity-checks every node whose outgoing edges are known, and then checks
  extents, line breaks, heights and balance on every expanded branch.
- `Proposal.edict` computes ContentAddressV1 ids for every arena node in
  arena order, and emits the normalized proposal over the reachable fresh
  nodes only. A repeated id with the same atom is emitted once; with a
  different atom it is a conflict. Slicing never narrows a byte bound, so a
  fresh atom keeps its largest piece's bound (25,344 bytes). The lawpack's
  node write admits that bound.
- `Plan.edict` is the pure plan over one closure read. It checks the Head,
  loads the validated arena, and constructs the new tree: the leaf rewrite,
  or join(join(prefix, fromBytes), suffix). It then checks character
  boundaries and the no-op, counts the counters, and builds the proposal.
  Its outcome code follows the documented check precedence. The closure now
  starts at the basis Head and follows root, left and right edges, so the
  Head row and an empty Head need no separate read.
- `ReplaceRange.edict` is the effect intent, built by
  `rope/edict.application.json`. It reads the Buffer atom and its
  canonicalHead, checks the basis, the range order and the replacement,
  reads the Head's anchor, and makes one closure read. It then maps the
  plan's outcome code to its typed obstruction. On success it ensures every
  fresh node and edge in bounded `for` loops, ensures the new Head with its
  root and anchor edges, retargets canonicalHead, and bumps `Buffer.version`
  with a `ReplaceAtom` guarded by Echo's attachment-value digest of the atom
  it read (`echo.dpo@2.attachmentValueDigest`, echo#1011).
- The codec parsers are total, reporting `ok`, so the selector and the fold
  steps can use them. The `decode*` functions are the failing forms.

`rope/edict.lawpack.json` is the `jedit.text@2` lawpack, generated by
`tests/rope-lawpack.mjs`. It holds the envelope constants, the obstructions,
and the effect bindings for `echo.dpo@2`: node-atom and outgoing-edge reads,
and node and edge ensures and replaces. The graph schema and footprint law
come from the #404 fixture profile's type ids. The profile, Target IR and
intrinsic catalog pins in `rope/echo-dpo-2-profile.json` are copied from Echo
PR #990 at `aa2b5816`, so they change when that PR lands. Its budget is a
v1-schedule reference ceiling, not the envelope: the envelope budget will be
measured under v2 once amblicit#330 lands. The closure-read binding is not yet in the lawpack. `rope/vendor/jedit-text-2/` is the public
compiler's lawpack build output.

`tests/runtime-cases.mjs` prepares the 40-row runtime runner. It turns each
retained row, and each schema-2 addition, into a runtime case: the basis
graph with resolved type ids, the intent's exact input, and the row to
satisfy. A node that ordinary admission refuses is marked as a raw-store
witness. The Rust consumer, which installs a case, invokes the locked
package and reports an observation for the row judge, waits for a package
that Echo admits.

`rope/probe/BasisRead.edict` is a basis-read witness: the first DL-0159 step
alone, built with `rope/probe.application.json` and the closure-free lawpack
`rope/basis-read.lawpack.json`. Echo main `0d1f74a0`'s provider accepts it.
Echo's runtime admission still refuses the same package as an invalid
authored-effect program, so it has not executed. Comments sit after the
`use` lines in every source, because a comment before them breaks Echo's
source-alias check (echo#1022).

`rope/runtime/` is the test-only runtime consumer on Echo's public
`EffectPackageHost` (`trusted_runtime` only). Its smoke test runs Echo's
retained public link package end to end.

`tests/rope-modules.mjs` lists the modules in dependency order and pins each
`use module` import to its dependency's source digest.
`tests/rope-sources.spec.mjs` checks that the generated tables and every pin
are current.

What the public compiler does with these modules at Amblicit `7dbcbc23`:

- The modules compile to Core and Target IR.
- Echo `d527f47`'s provider refuses the package, because it does not support
  checked integers (echo#998).
- The checked-integer provider at echo PR #1004 `fcb54673` accepts each codec
  helper on its own.
- That provider refuses all four atom encoders together with "the package
  exceeds the host response budget". Amblicit's application build caps a
  provider response at 64 KiB (`response_limits` in
  `crates/amblicit-cli/src/application_build.rs`). The complete operation
  will be far larger than that, so this cap blocks the full build until
  Amblicit raises it.

Under the default v1 cost schedule, `join` alone needs at least 5,949,016,807
static steps and 15,228,165,577 allocated bytes. That is the compiler's
`InvalidBound` report against the declared budget. The v2 shared-read
schedule cannot yet be selected from a CLI application build; that is an
Amblicit gap.

Echo's verifier refuses
ContentAddressV1 intrinsics called inside a source helper ("the
effect-program judgment refuses the package"), although the lowerer accepts
them; computing ids in a fold needs that. Each module compiles to Core and
Target IR on its own.

Against Echo main `93684efd`'s provider, the whole plan compiles to Core and
Target IR, and the provider lowerer then fails with "provider guest resource
growth was denied". The modules pin Echo main `1e0228f2`'s `echo.dpo@2` profile (`7cadb97e…`).

The arena is split into a read-only stored list (at most 256 closure nodes)
and two small fresh lists (16 leaves and 128 branches). Folds append only
to the fresh lists. Leaf bytes are decoded from closure rows when needed.
Fresh ids are computed over the fresh lists only. The proposal lists the
arena indexes to emit, deduplicated by id, and the intent builds each write
inside its loop. A ContentAddressV1 id commits to the node type, the atom and
the full edge set, so equal ids mean equal content; the separate
same-id-different-atom check would need a BLAKE3 collision and was removed.

Built through `rope/edict.application.json` with Amblicit `738d3da7`, the
whole program parses, resolves and type-checks. It then fails the budget
check under the v1 schedule: 2,236,089,839,033 static steps and
11,338,540,947,802 allocated bytes. That is a v1 reference figure only.
Echo's effect-program configuration also caps `maxAllocatedBytes` at
16 MiB. The v2 figure the amblicit#330 agent measured for these modules,
26.5 MB, is above that cap.

None of these modules has executed yet.

## Reproduce

Run the build script inside Docker with copies of the exact Edict and Echo
checkouts. Do not mount host repositories or Git directories into the container:

```bash
EDICT_REPO=/path/to/edict \
ECHO_REPO=/path/to/echo \
CARGO_TARGET_DIR=/path/to/disposable-runtime-build-cache \
  ./edict/replace-range/tests/build.sh
```

`edict.toolchain-lock.json` pins the exact Edict commit and CLI release, Rust
toolchain, Echo commit, provider identity, provider manifest bytes, and lowerer
and verifier components. It also pins the Node and npm releases, the resolved
`cbor-x` package and integrity, and the package, lockfile, and CI invocation
bytes that perform validation. The script refuses non-Git roots, wrong commits,
dirty checkouts, or validation-environment drift before invoking either
toolchain. GitHub's package-chain job checks out and verifies the literal pull
request head; ordinary matrix jobs may separately exercise the synthetic merge.

The harness reads Cargo workspace metadata to select exactly one public CLI
(`edict-cli` / `edict` on historical pins, `amblicit-cli` / `amblicit` after the
compiler rename). The build lock's source closure includes the compiler-selection
helper, so changing selection invalidates the locked proof. It builds that package and binary with the pinned Rust
toolchain and takes the compiler executable path from Cargo's successful
`compiler-artifact` output. `CARGO_TARGET_DIR` may therefore point outside the
Edict checkout, as it does in CI; no pre-existing `target/debug/edict` is needed.
The runtime witness uses the same configured build cache. A regression runs the
full package chain against an isolated Edict checkout whose default binary path
is absent before and after execution.

`edict.build-lock.json` binds the exact source and validation closure to the
Core, Target IR, result projection, executable package, verification report,
and executable-subject identities. The raw Echo report remains a separately
identified artifact. A canonical-JSON Jedit evidence envelope binds that artifact
and subject to the exact provider release, verifier component, diagnostic ABI,
report ABI, and outcome; that verifier-specific envelope is the transitional
`VerificationReportId`. `edict.executable-subject-lock.json` separately records
the subject identity and the exact package, Target IR, and result-projection
references it contains. The harness recomputes every digest from emitted bytes
and refuses a valid report paired with a substituted package or verifier. The
locks contain no self-referential Jedit commit; an exact PR head remains an
external review coordinate.

The script verifies the committed `jedit.text@1` closure through Edict's public
lawpack `checkOnly` boundary. It never republishes or repairs that authoritative
tree. It then copies Echo's checked provider package into `.build/`, invokes
Edict's public application build, and requires the generic pure package and an
accepted independent-verifier report. Snapshots cover the application inputs
outside `.build/`, the pinned project validation files, and every tracked Edict
and Echo file; any content, identity, or timestamp mutation fails the run. Only
`.build/` is disposable output. `CARGO_TARGET_DIR` optionally selects a shared
disposable Cargo cache; otherwise runtime build output stays under `.build/`.
The runtime witness runs with `--locked` and must emit its completion marker
after all assertions pass, so a zero-test Cargo invocation cannot satisfy the
gate. The provider and the runtime are both pinned to the same Echo main
commit. Neither is described as a released or installed product dependency.
Distinct nominal `BufferId` and `HeadId`
contracts retain the same exact 32-byte representation, while a negative
compiler witness proves that neither can cross the imported lawpack boundary as
the other.

The next gate must exercise an authored rope consequence under generic Echo
stateful execution and compare it with the independent oracle. This pure
boundary witness is not a substitute for that evidence.

## Moving to new Echo and Edict commits

`scripts/deps/echo-edict-relock.mjs` moves Jedit to the Echo and Edict commits checked out in two clean checkouts and regenerates everything derived from them: the host's and conformance runtime's Echo pins, the host's Wesley contract bindings, the ReplaceRange oracle, this lawpack's oracle digests and target-adapter profile and IR references, the vendored `jedit-text` publication and the source's import digest, the toolchain lock, and the build and executable-subject locks. It then runs `tests/build.sh`. Run it with the Node, npm, and Rust releases this toolchain lock pins:

```bash
node scripts/deps/echo-edict-relock.mjs --echo-repo /path/to/echo --edict-repo /path/to/edict
```

It refuses to start unless the files it manages are clean, and any failure (a host that no longer compiles against the new Echo, a refused build, a broken package chain) restores them and removes anything the run created, so a failed relock leaves the tree as it found it. A host that stops compiling is source work, not relocking.

The provider applies a conservative whole-operation static judgment, including
copies and scans at the source byte bounds. With the pinned toolchains, public
builds refused the previous 8,388,608-step / 16,777,216-byte envelope, then
accepted the selected conservative envelope of 134,217,728 steps and
268,435,456 allocated bytes. The refusals report generic
`core.source-functions` unsupported semantics, not a specific budget diagnostic;
the budget attribution comes from the contrast runs. The minimum sufficient
envelope and maximum-input runtime cost have not been established.

These are conservative admission ceilings, not measured execution costs. The
output ceiling remains 8,388,608 bytes, and the source byte bounds are unchanged.
Each runtime host still supplies its own smaller limits; the resource-refusal
tests retain theirs. The [component ownership contract](../../docs/jim-component-ownership.md#the-complete-cast-and-each-components-territory)
owns the distinction between application admission ceilings and Echo runtime
limits.
